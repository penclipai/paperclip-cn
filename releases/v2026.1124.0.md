# Paperclip v2026.1124.0

> Released: 2026-11-24

本次更新持续完善智能体运行、任务恢复、技能管理、Routines 编排与连接能力，并将 Paperclip CN 同步追平至上游最新功能、模型支持与安全修复。

## 亮点

- **智能体列表更便于筛选。** 智能体列表增加按模型、状态、运行方式和连接的筛选，便于在较大团队中定位需要处理的智能体。
- **运行中的后续消息更易读。** 补充指令会显示已提交的截图，并正确渲染 Markdown；适用的 Codex 和 Pi 任务仍提供短暂的编辑或取消窗口，随后将消息送入当前运行。
- **恢复和重试的反馈更清楚。** 当控制器、远程工作区或运行器在执行中断开时，系统会依据已持久化状态继续处理；「重试」会说明尚未完成的子任务或依赖，而不是无提示地失败。
- **Routines 页面全新改版并支持实时测试与自然语言管理。** 重新设计的 Routines 页面对齐常用视图与控件，支持再次测试 live webhook，智能体也可以用自然语言为负责人列出或调整例行任务。
- **实验性的领域与职责（Areas & Responsibilities）看板上线。** 新增负责领域与职责面板，可将公司技能归档到对应职责下，并允许智能体在可控撤销的前提下协助维护成员职责。

## 改进

- **OpenCode 本地 Runner 默认复用任务会话。** 符合条件的本地 OpenCode Runner 可在同一任务的后续轮次中复用已有会话，减少重复启动的等待；每轮仍会重新校验授权。Pi 继续按轮次启动会话。已有智能体不会自动迁移，仍可选择 `Legacy runner`。Linux Runner 需要 GNU libc 2.39 或更高版本；Windows、Linux musl 或条件不满足的环境会使用兼容路径。
- **技能更新差异可由 API 读取。** 对跟踪 GitHub 来源安装的技能，`GET /api/companies/{companyId}/skills/{skillId}/update-diff` 提供已安装版本与最新跟踪版本的逐文件统一 diff。该接口只读，不会应用更新；无法比较或超过大小预算的文件会说明原因。
- **模型、Runner 与适配器持续扩展。** 新增或完善 Claude Fable 5.2 与 GPT-6.2 支持并更新 CLI/SDK 最低版本约束；Antigravity CLI 与 ACP `/plan` 只读模式、原生集群及供应商认证持续完善；Grok、Copilot 与 OpenCode 凭据可传递给插件 Runner；任务释放或重启后可在下次运行时继续拉起。
- **连接能力增强且 MCP 助手连接毕业。** Assistant connections (MCP) 从实验特性正式转正；Google Workspace（Gmail、Drive、Docs、Sheets、Slides、Calendar）支持 REST 工具、结果大小限制与移除连接时同步终止 Google 访问授权；新增引导式 AWS 角色与按连接签发临时凭据（含 CloudFormation 模板）及每家公司独立的工作负载身份签发能力；配置过程支持展示来自个人智能体的实时进度。
- **中文体验持续打磨。** Paperclip CN 追平最新语义化翻译目录并审阅既有界面中的中文文案，使操作、错误提示和状态表达更自然；事件 ID、包名、命令、模型与 provider 标识仍保持原样。

## 兼容性与升级注意事项

- **升级会执行数据库迁移。** 相对 `v2026.1026.0`，本次更新包含 `0378`–`0504` 共 127 个迁移，涉及运行恢复、控制器租约、工作区、预算恢复声明、密钥提案级联、Routines/职责、工作负载身份及索引等持久化调整。升级前请备份数据库和实例数据。首次启动后等待迁移完成；如需回退，请恢复与旧版本匹配的完整备份，不要只替换应用文件。
- **Pipelines 实验功能已移除。** Pipeline 看板、阶段设置、相关 CLI 命令、`pipelines:write`、`enablePipelines` 和任务详情中的 `linkedCases` 不再提供。已有 Pipeline 表与记录不会因这项移除而自动删除；Cases 和 Routines 继续可用。
- **运行历史列表改为有界返回。** `GET /api/companies/{companyId}/heartbeat-runs` 默认最多返回 200 条，最高可请求 1,000 条。依赖无上限返回的 API 客户端应显式传入 `limit`。
- **删除智能体说明文件需要明确确认。** 使用 `penclip agent instructions-file:delete` 时必须传入 `--yes`。
- **自定义 Docker 镜像需要检查启动命令。** 随附镜像以 `node server/dist-runtime/index.mjs` 启动；仍以 `tsx server/dist/index.js` 作为入口的自定义镜像应在升级前调整。

## 既有可选能力的使用条件

升级后继续使用以下功能时，请确认相应的配置、数据流向和费用条件。

- **智能体观测、浏览器分析与模型驱动的提示注入检查。** 观测默认关闭，可使用 Braintrust（美国）或自定义 OTLP HTTP 端点；启用前请确认数据接收方、采集范围、保留策略和费用或合规要求。会话回放默认展示界面骨架，仅对客户业务内容进行掩码保护，并支持欧盟/英国/瑞士访客的同意提示。提示注入检查需要共享 OpenRouter 连接和模型，会向所选模型发送经过脱敏的工具结果，调用费用计入 Costs。
- **Google Workspace 与实验性外部智能体。** 统一 Google Workspace 连接仍依赖支持相应请求的 Paperclip 托管 OAuth broker。Grok Bot 需要 Assistant connections (MCP)、Paperclip Runner、已认证登录和 HTTPS `PAPERCLIP_PUBLIC_URL`；Muse 需要 Paperclip Runner 和可公开访问的 HTTPS。Speko 通过既有 Chat connectors 设置接入，需要其自身的 API key、agent ID 和公开 HTTPS 回调；其服务费用和可用性由 Speko 单独决定。
- **Sentry 运行失败上报。** 仅设置 `SENTRY_DSN_BACKEND` 不会自动上报运行失败。需要筛选意外失败时设置 `PAPERCLIP_SENTRY_RUN_FAILURES=unexpected`；需要上报所有失败或超时时设置为 `all`。

## 修复

- **运行日志与失败反馈更稳定。** 对象存储中的运行日志尾部支持并行读取与缓存；对安装体积超限等不可恢复运行设置停止无效重试；已终止运行的延后 Attempt 日志归档更可靠。
- **重启、离线/在线迁移与工作区恢复更可靠。** 对已确认但在控制器重启、远程保存或运行器中断期间未完成的步骤，系统会根据已持久化状态继续恢复；在线持久数据迁移与工作区/技能源校验的阻塞诊断更明确；公司删除、首次取消登录清理、GitHub PR 评审/状态评论和 Daytona 区域代理兼容性亦同步修复。
- **任务打开、子任务取消与对话发送更可靠。** 任务视图恢复个人归档与活跃子任务取消确认；外部对话发送保留草稿和请求标识，并在未知结果时允许安全重试，避免重复投递。

## 升级指南

1. 正常停止现有实例，并备份数据库和实例数据。
2. 升级后等待 `0378`–`0504` 号迁移完成，再检查公司、智能体、任务、Connections 和模型设置。
3. 若使用 Runner，请确认主机平台满足要求；不满足条件时继续使用 `Legacy runner`，不要强制迁移已有智能体。
4. 检查使用 `GET /api/companies/{companyId}/heartbeat-runs` 的自建客户端，必要时明确设置 `limit`。
5. 检查依赖 Pipeline 功能、旧 Docker 启动命令或无确认删除命令的自动化，并按上述兼容性变更调整。
6. 如需继续使用观测、提示注入检查、Google Workspace 或实验性外部智能体，请先确认连接、数据接收方和费用设置。
7. 如需回退，恢复与旧版本匹配的数据库和实例数据备份。

## Windows 安装提示

本次 Windows 安装包未进行代码签名。Windows SmartScreen 或 UAC 可能显示“未知发布者”。请仅从本项目的 GitHub Release 下载，并使用同一发行页的 `SHA256SUMS.txt` 校验安装包。
