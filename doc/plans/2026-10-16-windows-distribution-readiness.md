## 执行顺序与完成证据

1. 修复桌面打包后工作区 AI SDK junction 被实体目录覆盖的副作用。先复现和回归，再修复部署隔离；
   完整打包前后检查原依赖路径类型、目标、版本与可导入性，不再依赖人工恢复。
2. 补齐 NSIS TEMP/TMP 恢复边界，使用真实编译探针验证短/长路径、空格参数、退出码、清理、
   未设置变量和构建卸载器旁路；把同一探针接入 Windows CI 并保留证据。
3. 补齐审计列表宿主插件动作的中文，保留原始事件 ID、包名和用户内容；聚焦测试与安装版可见结果
   同时验证。
4. 冻结本轮源码后完整构建 Windows 包。保留上一版安装器和最终验收证据；仅对有本任务安装收据和
   注册身份的安装执行卸载/覆盖。分别验证完整包全新安装、升级、卸载后数据保留、全用户/UAC。
   每次安装核对完整文件清单、注册位置；运行数据和临时路径均在 D 盘，不接触 3100 开发实例数据。
5. 在安装版创建独立验收公司和 D 盘工作区，用已授权 Grok CLI 完成有界真实任务，核对产物、
   工作成果、运行日志和任务结果；使用正式取消/暂停/恢复接口验证停止与恢复，不用杀进程模拟。
6. 运行相关聚焦和广域检查，提交并推送，修复最新提交的 CI。按实际仓库的评审和保护要求推进
   PR 就绪与合并；不把旧检查、自动安全检查或历史验收替代本轮证据。
7. 检查通过后提出正式版本号、Windows 签名接入和发布流程。未确定发布主体与证书前不购买证书、
   上传密钥或发布 stable；按维护技能与 doc/RELEASING.md 的当前渠道规则执行后续发布。

- 不读取 npm recovery codes，不在日志输出任何凭据；Grok 复用已有授权并限制任务范围和轮数。
- 系统 UAC 提示需要本机用户确认时，在实际提示出现后请求配合；独立工作继续进行。
- 不重试此前被自动审批拒绝的目录删除，不以其他文件 API 绕过该拒绝。
- 项目文档要求 Greptile 5/5 且无遗留意见；合并前核查是否有该评审或明确有效的仓库例外，
   不自行改写门槛。遥测变更按 AGENTS.md 的隐私审查要求处理。
